# Copy trading (live, 2026-10-23)

A follower picks a public trader ("leader") on SoDEX or Hyperliquid, sets their
own rules, and copies run on **SoDEX perps in the follower's own account**, with
a key the follower registered there. ValueDesk never holds funds.

## Three modes, one engine

| | This browser | ValueDesk executor (hosted) | Self-hosted |
|---|---|---|---|
| Runs | in an open ValueDesk tab (one tab per browser holds a Web Lock) | `valuescan-executor` on the Tokyo instance, 24/7 | `valuedesk-copier.mjs` (or Docker) on the follower's machine |
| Copy key | `vd-copy-browser`, generated in the browser, vault slot `copy`, max 7 days | `vd-copy-tokyo`, generated by the executor, AES-256-GCM sealed (`kek` file), max 180 days | `vd-copy-self`, generated by the copier, sealed in `copier-data/`, max 180 days |
| Key engine | perps only | perps only | perps only |
| Instructions | clicks in the tab | EIP-712 `CopyRequest` signed per change, kept append-only | EIP-712 `CopyRequest`, kept by the copier |
| Leader feed | SoDEX `trade` stream (bi/si), Hyperliquid `userFills` | SoDEX `trade` stream, Hyperliquid `trades` on every coin | SoDEX `trade` stream, Hyperliquid `userFills` |
| Reached by the site | itself | `/api/copy/v1/*` (Vercel edge -> Caddy -> 127.0.0.1:8799) | `http://127.0.0.1:<port>/api/copy/v1/*` (loopback only, CSP) |

The engine is `packages/copy-engine` (MIT): settings, the region policy and the
copy fee ladder (`policy.ts`), the planner (`planner.ts`), the SoDEX and
Hyperliquid clients, the feeds, order sinks (`KeySink`, `PaperSink`), the runtime
and the signed API contract (`api.ts`). The executor is `apps/executor` (MIT):
`node:http`, `node:sqlite`, no framework. The web side is `apps/web/src/copy/`
(`live.ts` is the store over the three modes, `browserCopier.ts` mode 1,
`executor.ts` the API client, `sodexSetup.ts` the SoDEX signatures,
`CopySetupSheet.tsx` the setup sheet and its steps) and the Copy page in
`apps/web/src/components/copy/`: the trader grid (`Discover.tsx`, `TraderCard.tsx`,
`gridModel.ts`) with the copy score and, on the Counter-trade tab (the boards'
`side=worst` hundred), the counter score (`copyScore.ts`: 25 return, 20 edge per
traded dollar beyond ~12 bps of copy costs, 15 profit, 15 win rate by the end of
its 95% Wilson interval, 15 account size, 10 track record; return and profit as
percentiles of the board on screen; a trader on the wrong side of the window at
most 30; shown with "not a recommendation"; copy cards glow green, counter cards
red, as the order ticket's two sides), the two-step copy dialog
(`CopyModal.tsx`: rules with a replay of the trader's fills, then where it runs,
the amount and the mode's signatures), one trader's page and My copies
(`panels.tsx`).

### Manipulation protection (ready, not wired in)

`packages/copy-engine/src/priceGuard.ts` builds one reference price for a coin from
SoDEX, Hyperliquid, Aster and Binance (`fetchQuotes`; each venue 5 s at most, 1000x
contracts scaled to one coin) with a weight per venue, as a weighted mean or
median, dropping stale quotes and outliers (`referencePrice`). Two checks use it:
`triggerHit` (a stop or a conditional fires on the reference, not on one venue's
wick) and the optional `marketOrderAllowed` toggle (a market order goes only while
the venue is within the slippage range of the reference, against you). Nothing
calls it yet - the planner, the guards, the order ticket and the algo orders can.
A browser caller also needs fapi.asterdex.com and fapi.binance.com in the CSP.

### Counter-trading

A copy has a direction (`CopySettings.direction`, 2026-10-23): `copy` takes the
trader's side, `counter` the other side. The planner (and the backtest engine,
`components/copy/sim/engine.ts`) then decides on the leader's position mirrored,
-L: their long opens your short of the size your rules give, their reduce, close
or flip is your reduce, close or flip the other way. Caps, stops and the region
limit are unchanged; the leader's own books (positions, the leader curve) stay real.

- **Signed only when it matters.** `canonicalSettings` writes `direction` only for a
  counter-trade, so every copy signed before stays byte for byte the same; a missing
  direction is a copy. A running copy cannot switch direction.
- **Never to an executor that would ignore it.** Unknown rule fields are ignored, so an
  older executor would COPY a counter-trade. Executors from 1.1.0 list `counter` in
  `info.features`; the site (`copy/live.ts` `supportsCounter`) refuses to start a
  counter-trade on one that does not, and says to update a self-hosted copier.
- **Terms 2026-10-23.2** name the direction (section 3) and its risk (section 7), and the
  risk summary in the app has a line for it: every follower accepts them again.

### What a copy does

- Every leader position change (stream print, coalesced 150 ms per market, or a
  1-minute REST reconcile) is planned per follower: target by notional
  (proportional / fixed ratio / fixed amount), increases never shrink, decreases
  follow the leader's fraction, flips close then reopen. A decrease or increase
  while the copy is on the other side (a missed flip) is a flip too.
- The leader's fraction is kept as the copy's size per leader unit (fixed amount:
  its adds too), so scale-outs and adds too small to trade one by one (below one
  lot or $10) add up and are caught up by the next step, never lost.
- Orders sent but not yet booked count as held: a second leader fill before the
  first copy order is booked is not copied twice, and the gross leverage cap
  (the EEA 2x cap with it) counts orders in flight on every market.
- A reconcile's REST answer is as old as the moment its read started: a market
  the stream printed on since, or is still merging, is left to the stream.
- Caps in order: max position, gross leverage (the lowest of the follower's cap,
  the **EEA 2x cap**, the market's), market order limits, step, minimum notional,
  then the follower's **free margin** on SoDEX: an opening order it does not cover
  (at the copy's leverage, plus the taker fee) is skipped ("not enough free
  margin in your SoDEX account") instead of sent to be refused. Reductions are
  never gated; a flip counts the margin its close frees.
- The copy's leverage is set on SoDEX before an opening order and remembered only
  once SoDEX took it (tried twice); until then only reductions go out.
- A leader size that is not a number is ignored, never read as flat.
- Orders are IOC limits at the SoDEX mark +/- the slippage cap, inside SoDEX's
  band; every follower of an event gets the same reference price, in random order.
- Positions open when copying starts are left alone until the leader is flat
  (unless "copy existing"); a market the follower holds by hand is left alone.
- Stop-loss / take-profit: copier-side at the marks AND as SoDEX position stops
  (reduce-only, mark trigger) so they hold while no copier runs; drawdown stop
  halts the copy.
- A live copy is `blocked` (and resumes by itself) without a registered key, a
  builder approval of at least 0.025%, or an allowed region. The region is checked
  first, without SoDEX, and again on every leader change, so a failed SoDEX read
  never leaves a blocked region copying.
- "Ask me each time" needs a copier that can ask (the browser): on the hosted or a
  self-hosted executor a new copy with it starts `blocked` with that reason, and
  changing a running copy to it is refused.
- A `blocked` or `halted` copy places nothing new but still follows the leader's
  reductions and closes (reduce-only), and its stop-loss / take-profit / drawdown
  guards keep running.
- Catch-up: after a restart, what the leader changed while no copier ran is
  planned like a missed print (a position opened meanwhile counts as pre-existing);
  on every reconcile and on resume, what a copy holds where its leader is flat or
  on the other side (a close that filled only in part, a close missed while
  paused, a remainder on a market a stop-loss detached) is closed reduce-only.
  A guard close detaches its market only once SoDEX took it.
- Lowering (or raising) the allocation moves the drawdown stop's peak by the same
  amount, so it never reads as a loss.
- Stop and close says "positions closed" only for positions known to be flat (paper
  books, or the follower's account re-read); the SoDEX stop-loss of one that may
  still be open is kept, and the status names it. Stop and keep leaves the kept
  positions' SoDEX stops in place.
- Signed writes are never retried; the account is re-read after orders and every
  30 s, and the copy's books follow what SoDEX says. Fills come from the public
  stream by the follower's account id.
- Paper copies run the same way against the live leader and send nothing.

## Owner decisions (2026-10-23)

- Hosted executor **live for every allowed country**.
- Copy fee: the copy ladder on **every** copied order in every mode -
  2.5 bp under $100k of 14-day volume, 2 bp from $100k, 1.5 bp from $500k,
  1.2 bp from $2M, 1 bp from $10M. Followers approve a 0.025% ceiling on SoDEX.
- Blocked: US + territories (US PR VI GU AS MP UM), CU IR KP SY RU BY MM; from
  2026-10-27 (terms 2026-10-27.3) also the United Kingdom (GB; `UK` is read as GB;
  not JE GG IM or the Overseas Territories) and Canada (CA) - the site is
  close-only there as in the US.
- Sanctioned wallets (2026-10-27): the executor refuses a follower or a leader on
  the sanctions list (`packages/copy-engine/src/sanctions.ts`, a list in the repo
  from the Chainalysis oracle, refreshed with `node scripts/update-sanctions-list.mjs`)
  at accept-terms, key create/import, subscribe, update, resume and algo start/resume,
  and holds what already runs; stopping, cancelling and deleting the key stay open.
  The API signs no builder fee terms for a listed wallet.
  EEA residents (EU + IS LI NO, and the EU's own-code territories RE GP MQ GF YT
  MF AX): copies capped at 2x. The stricter of the
  declared country and the IP country (hosted, Vercel `x-vercel-ip-country`) applies.

## Legal safeguards built in

What the product does for its users before and during a copy.

1. **Terms before any copy**: `/copy-terms` (legal/copyTerms.ts, version
   `2026-10-23`), accepted by ONE wallet signature carrying the version, the
   keccak256 of the exact text, the declared country and four statements (adult;
   not a US person; chose the trader and every rule themselves; read the risks).
   ValueDesk's executor records every acceptance, in every mode.
2. **Every instruction signed and kept**: subscribe, update, pause, resume, stop,
   stop all, key create/delete - each an EIP-712 message the wallet displays as
   readable JSON, verified (signer, executor id, deadline, nonce) and stored
   append-only before it takes effect (`consents` table). Followers can read
   their own record (`GET /api/copy/v1/consents`).
3. **No personal recommendation**: traders shown by public, objective metrics,
   the same for everyone; no "suggested for you"; "Not investment advice" next
   to the start button; past performance caveats in the backtest and the terms.
4. **The follower decides everything**: leader, sizing, caps, stops, coins,
   margin mode; the executor never changes a rule; optional "ask before each
   trade" in browser mode; paper mode to try a rule without orders.
5. **Regions**: declared country required; IP country checked by the hosted
   executor; blocked countries refused at terms, at start and at runtime
   (`blocked`); EEA 2x cap enforced by the planner and on the SoDEX position
   leverage in every mode.
6. **Key hygiene**: copy keys are perps-only, separate from the trading key,
   short-lived (7 / 180 days), named per mode (re-approving replaces, never adds),
   sealed at rest; the hosted-key notice discloses that a SoDEX trading key can
   also move funds between the follower's own accounts; revoke in one click.
7. **Kill switches**: pause / stop per copy, stop all (every mode), stop and
   close, revoke the key on SoDEX (the hard stop), drawdown stop.
8. **Transparency**: activity log per copy (sent orders with limit price, actual
   fills, skips with reasons, status changes, errors), CSV export, fee per order.
9. **Fairness**: same limit price for all followers of an event, random order,
   no paid priority, no inducements to or from leaders; leaders are not paid.
10. **Self-host and browser modes are software the follower runs**: open source
    (MIT), the follower's key never reaches ValueDesk, the site talks to a
    self-hosted copier over loopback only.
11. **Privacy**: the policy covers what each mode processes, where (Vercel hnd1,
    AWS ap-northeast-1, Japan adequacy decision), legal bases and retention
    placeholders; the executor never stores IP addresses.

## Run it locally

```
node scripts/with-node.mjs --prefix apps/server run dev      # API :8797
node apps/executor/tools/dev.mjs                             # executor (hosted mode) :8799, data in %LOCALAPPDATA%/Valuescan/executor-dev
node scripts/with-node.mjs --prefix apps/web run dev         # site :5180, /api/copy -> :8799
cd apps/executor && npm start                                # a self-hosted copier :8799 (or PORT=...)
```
